# Contributing to Voxa

Start with the [build instructions](README.md#build-and-run). Open an issue first for changes to audio routing, provider protocols, or transcript storage. Small fixes and documentation improvements can go directly into a pull request.

For an audio or translation report, include the Voxa and macOS versions, provider, input and output device types, and whether the problem affects captions, playback, or both. Use a synthetic audio clip or text that you can share publicly. Omit API keys and private conversations.

Run the [development checks](README.md#development) before opening a pull request. Test capture and playback on a real Mac when changing audio routing. Describe the source, output device, expected behavior, and what you observed so another contributor can reproduce the check.
